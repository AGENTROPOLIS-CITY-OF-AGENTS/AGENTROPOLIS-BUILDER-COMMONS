# AGENTROPOLIS Design System — Builder Commons Profile

Builder Commons uses the **AGENTROPOLIS Design System** as a hard product requirement.

## Core visual language

- obsidian / black foundation
- cyan + red primary system signals
- controlled lime, hot-pink, and purple accents
- liquid-glass / translucent panels where useful
- cyber-noir presentation with strong information hierarchy
- spatial depth without sacrificing legibility
- mobile-first responsive behavior
- XR-aware interaction design
- accessible 2D equivalents for meaningful 3D operations

## Builder Commons components

The Builder Commons profile extends the parent system with:

- project-room cards
- human presence indicators
- agent presence indicators
- authority / mandate status
- build-state HUDs
- repository and PR surfaces
- opportunity / bounty cards
- compute-node status
- broadcast / live-build controls
- contribution-evidence markers
- execution-receipt references

## Signal semantics

- **Cyan:** active infrastructure, navigation, healthy system state
- **Red:** consequential action, execution boundary, warning emphasis
- **Lime:** success, available, passing verification
- **Pink / Purple:** collaboration, creative, agent/runtime differentiation

Color never carries meaning alone. Text or icon state must accompany critical status.

## Rule

The 3D world may be cinematic. Core operations must remain clear, keyboard-accessible where practical, mobile-usable, and available through a non-spatial surface.
